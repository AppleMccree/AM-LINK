# AM-LINK：面向留学生的课堂学习辅助工具（当前版本说明）

老师您好：

这是我根据自己上课时的实际困难开发的一个 Windows 桌面应用，叫作 **AM-LINK**。我作为中文母语留学生，在日语、英语课堂、学术讲座和小组讨论中，经常需要同时完成听讲、理解术语、看 PPT、记录重点和准备发言。普通转录或翻译软件能解决其中一部分，但很难把课堂中的理解、提问和课后复习连起来。

因此，我尝试把它做成一个个人学习辅助工具，而不是单纯的实时翻译软件。下面内容以我**目前正在测试的版本**为准；我把已经可用、正在调试和仅作为后续设想的功能分开说明。

## 一、目前可以使用的功能

### 1. 实时课堂转写与翻译

软件通过电脑麦克风收集声音，先进行实时语音识别，再调用语言模型翻译。当前可选择：

- 日文 → 中文；
- 英文 → 中文；
- 日英混讲 → 中文；
- 中文 → 日文；
- 中文 → 英文。

界面会先显示会持续更新的临时字幕，识别稳定后再固定为正式记录。课堂模式中可以同时保留原文、中文译文和时间信息，之后可回看、复制或把字幕用于提问。

### 2. 独立双向同传

在面对面交流或小组讨论中，我可以打开独立的双向同传窗口：

- 左边显示“我说中文 → 给对方看的日文/英文”；
- 右边显示“对方说日文/英文 → 给我看的中文”；
- 每一侧都保留译文和原文，避免只看译文时无法核对；
- 系统会尝试依据识别语言、文字特征、发言顺序和本地学习到的音色特征自动分配左右两侧；
- 出现误判时，可以手动使用“对方连续发言”“我方连续发言”或“按住我来说”进行纠正。

这里的“音色学习”是对当前设备采集到的声音能量、过零率和频谱变化等简单声学特征进行本地统计，用来辅助判断“可能是我方还是对方”。它**不是**可靠的声源方位识别，也不能保证在多人重叠说话时把每个人的声音完全分离。复杂多人对话仍是当前版本最需要继续优化的部分。

### 3. 课程、课堂记录与录音

学习资料按“课程 → 每节课”组织。每门课程可新建、改名、归档；每节课可保存：

- 已确认字幕和译文；
- 时间线；
- 对应的录音片段；
- PPT / PDF 课件副本；
- 问 AI 的记录；
- 学习包和课后总结。

如果一节课因中断被拆成多条记录，当前版本支持将较晚的一节与上一节手动合并。历史课堂可重新打开，并查看当时的课件、字幕、问答和录音。

### 4. PPT / PDF 阅读与课件跟随

软件可以导入 PPTX 或 PDF，并把副本保存到相应课堂资料中。用户可以手动翻页、输入页码跳转；主界面中的 PPT 区和实时字幕区可以拖动调整宽度，方便投屏或按自己的阅读习惯使用。

当前版本已经有三种课件跟随模式：

- **手动浏览（默认）**：学生完全控制页面；后台仅记录字幕与当前页的关联；
- **智能提示**：系统根据已经稳定的字幕和课件文字给出可能的页面建议，但不会自行翻页；
- **自动跟随（实验）**：只在匹配结果足够稳定时跳转。学生手动翻页后，自动跟随会暂停，并可以点击“恢复跟随”。

我仍把自动跟随视为实验功能，不把它当作课堂中必须依赖的功能。

### 5. 在字幕中直接问 AI

当我看到不理解的字幕时，可以选中一段文字后右键点击“问 AI”；选中内容会自动进入问题框，也可以继续编辑、复制或粘贴自己的问题。

AI 回答会尽量参考当前这一节课的选中字幕、相关时间点、当前 PPT 页及课件文字，而不只是孤立翻译一句话。问答记录会保存到该课堂中，之后也会作为学习总结的材料。

这项功能依赖个人配置的千问 API，或已配置学校统一 Key 的云端课堂；网络、API 权限或额度异常时，问题会保留，但回答可能失败，需要之后重新询问。

### 6. 学习包与课后总结

结束课堂后，应用会先把本节课的字幕、课件文字和问答整理为资料包，然后在后台调用 AI 生成 `学习包.md`。由于生成过程在后台进行，用户可以继续查看记录，不需要一直停在总结页面等待。

目前学习包的目标是整理：课堂主题、核心概念、专业术语、教师强调内容、作业/考试/成绩评定线索、学生疑问和复习建议，并尽量保留时间点或 PPT 页码供核对。

这一部分已经可以使用，但仍在重点调试中：长课、网络波动和 API 限制可能导致生成慢或失败。失败时原始字幕、录音和课件仍会保留，可以之后通过“重新总结”再次生成。

### 7. AI 用量和费用查看

应用提供 AI 用量页面，按语音识别、课堂翻译、问 AI 和学习总结分别记录调用次数、音频时长、Token 等，并按公开价格规则估算美元费用。该费用是本地估算值，最终费用仍应以模型服务商的控制台账单为准。

### 8. 云端课堂学生端

当前桌面端已经有“加入云端课堂”的入口：学生可用六位课堂码匿名加入课堂、查看匿名问题板、点赞其他人的问题，或发送“没听懂”信号。断网时待发送的课堂反馈会暂存在本机，恢复连接后尝试补传。

这项功能需要对应的课堂服务器已经部署并提供课堂码；没有配置服务器时，AM-LINK 的本地同传和课程记录仍可独立使用。

## 二、我认为它与普通会议工具的不同

AM-LINK 不想替代 Zoom、会议纪要工具或专业同传。它更关注留学生个人在实体课堂、讲座和面对面讨论中的学习过程：

1. 将日语、英语等课堂内容即时转化为中文理解辅助；
2. 将课件、字幕、个人提问和复习资料放到同一节课中；
3. 允许学生在不打断课堂的情况下记录不理解之处、之后再回看；
4. 通过双向同传减轻留学生发言时的语言压力；
5. 让课后复习能够回到具体的时间点、原字幕和 PPT 页面，而不只得到一段概括性的总结。

## 三、当前限制与正在解决的问题

这个版本仍是持续测试中的原型，以下问题不能回避：

- 教室嘈杂、距离较远、语速快或多人同时说话时，语音识别和翻译会下降；
- 自动路由有时会把同一句话放到错误一侧，因此保留了手动纠正；
- 现阶段不具备可靠的声源方向定位或多人无损语音分离能力；
- 实时字幕、课堂结束和学习总结在网络或 API 响应异常时仍可能出现延迟或卡顿，我正在继续修复；
- AI 总结与回答可能误识别、漏掉信息或理解错误，不能代替教师说明、课程材料或学生自己的核对；
- 自动 PPT 跟随虽然已实现，但仍应视为实验功能，默认的手动浏览更安全。

## 四、后续希望继续完成的方向

1. 进一步改善多人小组讨论中的语言路由、重复字幕和插话处理；
2. 提高 PPT 匹配与智能提示的准确性；
3. 让课后总结更稳定地突出考试、作业、截止日期、出勤和成绩评定信息；
4. 在取得适当许可的前提下，完成教师网页端：匿名汇总学生问题和困惑热点，辅助教师发现群体性的理解困难；
5. 对系统在真实课堂中的延迟、术语准确率、学生理解负担和提问意愿做更系统的评估。

教师端的目的应是帮助发现“哪一个概念、哪一个时间点或哪一页 PPT 让许多学生感到困难”，而不是监控或评价个别学生。

## 五、数据和隐私考虑

个人课程、字幕、课件副本、录音和设置保存在使用者自己的电脑中。个人 API Key 不应被打包、共享或上传到公开仓库。课堂录音与资料保存应遵守学校、授课教师和当地法律的规定，并在需要时获得许可。

若之后使用云端课堂，设计目标是仅匿名同步学生主动发送的问题、点赞、时间点和相关页码；不上传学生姓名、完整录音、完整字幕或课件。

## 结语

AM-LINK 是我从“自己上课时到底哪里最容易跟不上”这个问题开始做的工具。它还不稳定，也有很多边界，但我希望它能探索一种更贴近留学生实际需要的学习方式：不是只把外语翻译成中文，而是帮助学生把听课、理解、提问、记录和复习更连贯地连接起来。
